# eivo-substrates

## Source of Truth

`domains.yaml` is the single source of truth. It defines everything the agent needs to generate the assets required to onboard platforms into Eivo. Each node covers a distinct part of the process:

- `def.families` — family base images (jvm, node, dotnet): used by the generation stage to build shared base images for `imageStyle: command` platforms
- `def.runtimes` — runtimes to install in the agent container: used by the agent stage to generate the agent Dockerfile; entries with `members` declare a group where the base provides a shared dependency and members extend it
- `def.domains` — flat list of all domains. Each entry declares `for` — the functions it supports (`environment-domain-ide`, `service`, `program`). Used by the generation stage to generate the corresponding assets and by the onboarding stage to provision them.

Read it before doing anything.

## Stages

**agent** — generates the agent Dockerfile. Read `agent/CLAUDE.md`. After generating, run `./build-agent.sh` to build and push the image before proceeding to any other stage.

**generation** — generates all platform artifacts. Read `generation/CLAUDE.md`.

**onboarding** — validates and provisions all platforms. Read `onboarding/CLAUDE.md`.

## Runs

Every invocation belongs to a named run. The run name is specified in the prompt:

```
run: full-run-1 — run all platforms priority 0
run: typescript-fix-1 — fix and re-onboard typescript-react
run: full-run-1 — resume
```

The agent reads the run name from the prompt before doing anything else. All generated output and the log for that run live under `work/runs/{run-name}/`.

## Log

The agent maintains a log at `work/runs/{run-name}/log.yaml`. Read it at startup before doing anything. Use it to skip already-completed steps and resume from where the previous run left off.

The log structure mirrors the generation order and onboarding phases exactly:

```yaml
agent:
  status: done | failed | pending

generation:
  domains:
    typescript-react:
      bootstrapper: done | failed | pending
      dockerfile: done | failed | pending
      scaffold: done | failed | pending
      pvc: done | failed | pending
      substrate: done | failed | pending
      crdtemplate: done | failed | pending
      onboarding: done | failed | pending
      readme: done | failed | pending
    python:
      bootstrapper: done | failed | pending
      dockerfile: done | failed | pending
      scaffold: done | failed | pending
      pvc: done | failed | pending
      substrate: done | failed | pending
      crdtemplate: done | failed | pending
      onboarding: done | failed | pending
      readme: done | failed | pending
  families:
    node:
      dockerfile: done | failed | pending

onboarding:
  domains:
    typescript-react:
      validate: done | failed | pending
      build_family: done | failed | pending
      build: done | failed | pending
      test: done | failed | pending
      plugins: done | failed | pending
      apply_pvcs: done | failed | pending
      scaffold_pvc: done | failed | pending
      deps_pvc: done | failed | pending
      plugins_pvc: done | failed | pending
    python:
      validate: done | failed | pending
      build_family: done | failed | pending
      build: done | failed | pending
      test: done | failed | pending
      scaffold_pvc: done | failed | pending
      deps_pvc: done | failed | pending
```

Rules:
- Write to the log after every step completes or fails — never batch
- If a step is `done`, skip it
- If a step is `failed`, retry it
- If `work/runs/{run-name}/log.yaml` does not exist, start fresh
- Never delete a run log manually — to fully reset a run: delete `work/runs/{run-name}/`, remove pushed images from the registry (`reg.jobico.local`), and delete provisioned Kubernetes resources (`kubectl delete pvc`, applied manifests)

## Structure

```
eivo-substrates/
├── CLAUDE.md
├── domains.yaml
├── Dockerfile              ← generated by the agent stage
├── agent/
│   └── CLAUDE.md
├── generation/
│   └── CLAUDE.md
├── onboarding/
│   └── CLAUDE.md
├── assets/
│   ├── generation/
│   │   └── lib/            ← github.sh, uri.sh
│   └── bootstrappers/
│       └── lib/
│           └── bootstrap.sh
└── work/
    └── runs/
        └── {run-name}/     ← all output for a named run, safe to delete and restart
            ├── {name}/     ← bootstrapper scripts per platform
            ├── generation/ ← platform artifacts + family images
            ├── substrates/ ← ADL objects
            └── log.yaml    ← run progress log
```
